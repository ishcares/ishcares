The sender's device compiled a deterministic canonical payload binding the exact fields:

tx_8f91c2d0-e14b | 25000.00 | merchant@pay.example | 8F91C2D4A3 | 1775480000000

Because the client signature only validated the hash of 2500.00, injecting 25000.00 produced a completely different SHA-256 digest. The server's ECDSA verification over NIST P-256 (secp256r1) failed closed instantly.

BioLock Verification Architecture

Traditional mobile payment flows authenticate the user (via biometric prompt or PIN), producing an authorization token that is transmitted alongside transaction parameters. If a rogue intermediary alters the payload, identity verification may still succeed even though the payment was tampered.

REFERENCE IMPLEMENTATION (Java 17 / ECDSAValidator.java): 
// Deterministic payload binding in BioLock
public byte[] buildCanonicalPayload(String txId, Double amount, String payeeUpi, 
                                    String challengeNonce, Long timestamp) {
    if (txId == null || amount == null || payeeUpi == null || 
        challengeNonce == null || timestamp == null) {
        throw new IllegalArgumentException("Payload attributes must not be null");
    }
    String canonical = String.format("%s|%.2f|%s|%s|%d",
        txId, amount, payeeUpi, challengeNonce, timestamp);
    return canonical.getBytes(StandardCharsets.UTF_8);
}

BioLock evaluates signatures via the Java Cryptography Architecture (JCA) using SHA256withECDSA over the secp256r1 (NIST P-256) curve. Transactions follow strict one-time state transitions (PENDING → VERIFIED or FAILED), failing closed on any deviation.
